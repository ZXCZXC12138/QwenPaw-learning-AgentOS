# 策略产品案例：长任务中"记忆失效"问题的策略设计与迭代

## 案例背景

**场景**：用户分多天使用 Agent 起草一份商业租赁合同。

**Day 1 — 第一轮对话**（Session A）：
> 用户："帮我起草一份商业租赁合同。出租方是'上海XX科技有限公司'，承租方是'北京YY贸易有限公司'。适用中国法律，争议解决选上海仲裁委员会。租金按月支付，每月 5 号前到账。另外注意：承租方要求有 3 个月免租期，这个一定要写进去。"

Agent 成功记录了所有关键信息，生成了合同初稿 v1。

**Day 1 — 第二轮对话**（Session A 继续）：
> 用户："把违约责任部分加上，逾期付款按日万分之五计算违约金。"

Agent 完成修改，生成 v2。用户关闭了对话窗口。

**Day 2 — 新会话**（Session B，全新 session）：
> 用户："继续，把争议解决条款写详细一些。"

**Badcase**：Agent 在争议解决条款中写了"适用**北京**法律，争议提交**北京**仲裁委员会"——完全搞反了。用户在 Day 1 明确说过"适用中国法律，争议解决选**上海**仲裁委员会"。

用户愤怒反馈："我昨天说了三遍上海！你怎么又写成北京了？"

---

## 第一步：从 Badcase 归因

策略产品经理打开 Langfuse 追踪链路，检查 Session B 的完整上下文：

```
Session B Turn 1:
  System Prompt: 2800 tokens
  用户消息: "继续，把争议解决条款写详细一些。" → 25 tokens
  召回的长期记忆: 0 条 ← ❌ 关键问题
  上下文总占用: 2825 / 128000 tokens（仅 2.2%）
```

**归因分析**：

| 可能原因 | 验证方式 | 结论 |
|---------|---------|------|
| 记忆未写入 | 检查 Session A 结束后 memory store 中是否有"上海仲裁"相关记忆 | 有 1 条模糊记忆："用户讨论了合同条款"——**未提取关键实体** → **根因 1** |
| 记忆未召回 | 检查 Session B 开始时 proactive trigger 是否触发 | proactive trigger 未触发——用户消息"继续，把争议解决条款写详细一些"与存储的记忆向量相似度仅 0.31，低于阈值 0.5 → **根因 2** |
| Session 隔离 | Session B 是全新 session，Session A 的短期记忆（scroll 上下文）未传递 | Session A 的完整对话历史在 Session B 中不可见 → **根因 3** |

**根因定位**：三层失效叠加——
1. **写入层**：记忆提取粒度太粗，"上海仲裁委员会"这个关键实体被泛化为"用户讨论了合同条款"
2. **召回层**：向量相似度阈值过高，"争议解决"与"合同条款"语义距离远，无法召回
3. **会话层**：跨 session 的短期记忆没有桥接机制

---

## 第二步：提出假设

> **假设**：如果建立三层记忆策略——(1) 关键实体/约束自动提取并结构化存储；(2) 基于任务上下文的智能召回（而非纯向量相似度）；(3) 跨 session 的项目级记忆摘要——则长任务跨会话的记忆准确率会显著提升。

---

## 第三步：设计策略规则

设计的记忆策略规则（对应 QwenPaw 的 `memory/` 子系统 + `context/scroll/memoryspace` + `proactive/`）：

```
记忆机制策略 v1：

=== 写入策略（When & What to Write）===

规则 W1：关键实体自动提取
  - 触发条件：用户消息中包含以下模式时，自动提取并写入长期记忆
  - 实体类型：
    · 机构名/人名（NER 识别）
    · 数字约束（金额、日期、比例、期限）
    · 选择/决策（"选X"、"用X"、"不要X"）
    · 偏好声明（"我喜欢"、"我希望"、"注意"）
  - 存储格式：结构化 JSON，而非自由文本摘要
    {
      "type": "constraint",
      "entity": "争议解决",
      "value": "上海仲裁委员会",
      "confidence": 0.95,
      "session_id": "session_A",
      "turn": 1,
      "timestamp": "2024-03-15T10:30:00"
    }

规则 W2：决策变更追踪
  - 当用户修改之前的决定时（"改成..."、"不对，应该是..."），
    旧记忆标记为 superseded，新记忆标记为 active
  - 保留变更历史（用于冲突消解）

规则 W3：会话结束自动摘要
  - 每个 session 结束时，自动生成结构化摘要：
    {
      "project": "商业租赁合同",
      "key_decisions": [...],
      "pending_items": [...],
      "user_preferences": [...]
    }
  - 摘要写入 project-level memory（跨 session 共享）

=== 召回策略（When & How to Recall）===

规则 R1：双路召回
  - 路径 A：向量相似度召回（现有机制，阈值从 0.5 降至 0.35）
  - 路径 B：关键词/实体匹配召回（新增）
    · 解析用户消息中的实体（NER）
    · 在 memory store 中精确匹配实体
    · 匹配到的记忆强制召回（不受相似度阈值限制）
  - 两路结果去重合并

规则 R2：任务上下文感知召回
  - 维护 project-level 上下文（当前在做什么任务）
  - 召回时不仅看当前消息，还看 project 上下文
  - 例：用户说"争议解决条款" → project 上下文是"商业租赁合同"
    → 召回所有与"商业租赁合同"相关的记忆

规则 R3：约束优先级
  - 约束类记忆（用户明确的要求/限制）优先级 > 偏好类记忆 > 事实类记忆
  - 约束类记忆在召回时加权 2x

=== 失效策略（When to Forget）===

规则 F1：显式失效
  - 用户明确否定（"不对"、"改成"、"不要"）→ 旧记忆标记 superseded
  - 用户明确删除（"忘掉之前说的"）→ 记忆标记 deleted

规则 F2：时间衰减
  - 记忆权重 = base_weight × decay(t)
  - decay(t) = e^(-λt)，λ 按记忆类型区分：
    · 约束类：λ = 0.01（几乎不衰减）
    · 偏好类：λ = 0.05（中等衰减）
    · 事实类：λ = 0.10（快速衰减）

规则 F3：冲突消解
  - 当两条记忆冲突时（同一实体不同值）：
    1. 时间优先：更新的记忆胜出
    2. 置信度优先：confidence 高的胜出
    3. 用户确认：如果用户明确说过"记住这个"，该记忆不可被自动覆盖
```

## 第四步：设计实验验证

设计了 A/B 实验，使用 200 个跨 session 长任务 badcase 回测：

| 维度 | 对照组（当前策略） | 实验组 v1 |
|------|-----------------|----------|
| 记忆写入 | LLM 自由文本摘要 | 结构化实体提取 + 会话摘要 |
| 记忆召回 | 纯向量相似度（阈值 0.5） | 双路召回（向量 + 实体匹配，阈值 0.35） |
| 跨 session | 无桥接 | project-level 摘要桥接 |
| 记忆失效 | 无衰减 | 时间衰减 + 冲突消解 |

**评测指标**：

```python
metrics = {
    # 核心指标
    "cross_session_recall_accuracy": 跨会话关键信息召回准确率,
    "constraint_compliance_rate": 约束遵守率（跨 session）,
    "user_repetition_rate": 用户重复率（用户需要重复之前说过的话的比例）,

    # 过程指标
    "memory_write_precision": 记忆写入精确率（写入的记忆有多少是真正关键的）,
    "memory_recall_rate": 记忆召回率（应该召回的记忆中有多少被召回了）,
    "memory_conflict_resolution_accuracy": 冲突消解准确率,

    # 负面指标
    "false_recall_rate": 错误召回率（召回了不相关/过时的记忆）,
    "memory_overhead_tokens": 记忆占用的额外 token 数,
}
```

## 第五步：实验结果与迭代

**v1 实验结果**（200 个跨 session badcase 回测）：

| 指标 | 对照组 | 实验组 v1 | 变化 |
|------|-------|----------|------|
| 跨会话召回准确率 | 23% | 76% | +53pp ✅ |
| 约束遵守率（跨 session） | 31% | 82% | +51pp ✅ |
| 用户重复率 | 45% | 12% | -33pp ✅ |
| 记忆写入精确率 | 38% | 71% | +33pp ✅ |
| **新问题：错误召回率** | 8% | **22%** | **+14pp ❌** |

**归因 v1 的新问题**：双路召回中，实体匹配路径过于激进——用户说"争议解决"时，召回了所有包含"争议"的记忆，包括 3 天前另一个合同项目中已被否决的方案。用户看到 Agent 引用了不相关的旧记忆，感到困惑。

---

## 第六步：策略迭代 v2

调整规则：

```
v2 改进：

召回策略增强：
- R1 增加 project 隔离：实体匹配召回时，优先匹配当前 project 的记忆
  · 同 project 记忆权重 × 3
  · 跨 project 记忆仅在无同 project 结果时才召回
- R2 增加时间窗口：默认只召回最近 7 天内的记忆
  · 超过 7 天的记忆需要更高相似度才能召回
  · 约束类记忆不受时间窗口限制（λ = 0.01 几乎不衰减）

失效策略增强：
- F3 增加 project 维度：冲突消解时，不同 project 的记忆不视为冲突
  · "上海仲裁"（合同 A）和"北京仲裁"（合同 B）共存，按 project 隔离
- 新增 F4：用户反馈学习
  · 用户说"不对"→ 被否定的记忆 confidence 降低 0.3
  · 用户说"对了"→ 被确认的记忆 confidence 提升 0.1
```

**v2 实验结果**：

| 指标 | 对照组 | v1 | v2 |
|------|-------|-----|-----|
| 跨会话召回准确率 | 23% | 76% | **89%** |
| 约束遵守率（跨 session） | 31% | 82% | **93%** |
| 用户重复率 | 45% | 12% | **5%** |
| 记忆写入精确率 | 38% | 71% | **78%** |
| 错误召回率 | 8% | 22% | **6%** |
| 冲突消解准确率 | N/A | 65% | **91%** |
| 记忆额外 token 开销 | 0 | +180 | **+120** |

## 第七步：策略产品化

验证有效后，将策略规则产品化：

1. **写入 Agent Core (memory/)**：
   - 新增 `EntityMemoryExtractor`：从用户消息中自动提取结构化实体记忆
   - 新增 `ProjectMemoryManager`：project 级记忆管理（跨 session 摘要）
   - 修改 `proactive_trigger.py`：双路召回逻辑（向量 + 实体匹配）

2. **写入 Loop Engineering 层**：
   - 新增 `MemoryConsistencyGate`（StopGate 的一种）：每次迭代后检查"当前输出是否与已存储的关键约束一致"
   - 不一致 → `INTERRUPT_AND_CONTINUE`，注入提醒："注意：用户之前指定了上海仲裁委员会"

3. **写入评测体系**：
   - 将"跨会话召回准确率"和"用户重复率"纳入常规回归评测集
   - 建立记忆质量 dashboard：记忆写入量、召回率、错误率、衰减曲线

4. **写入用户产品**：
   - 前端新增"记忆面板"：用户可查看/编辑/删除 Agent 记住的内容
   - 新增 `/memory` 命令：用户可主动管理记忆（查看、删除、强制记住）

## 案例总结：记忆机制设计的核心洞察

| 洞察 | 说明 |
|------|------|
| **记忆不是"存越多越好"** | v1 的错误召回率 22% 证明：过度召回比不召回更损害用户体验 |
| **结构化 > 自由文本** | 自由文本摘要丢失关键实体，结构化 JSON 保留精确信息 |
| **Project 隔离是关键** | 不同项目的记忆必须隔离，否则跨项目污染是主要错误来源 |
| **召回需要多路互补** | 纯向量相似度无法处理精确实体匹配，需要双路召回 |
| **失效策略和写入策略同等重要** | 没有时间衰减和冲突消解，记忆库会退化为噪声池 |
| **用户需要记忆的可控感** | 记忆面板和 /memory 命令让用户有"可干预"的安全感 |

## 记忆机制设计的策略框架总结

```
记忆机制 = 写入策略 + 召回策略 + 失效策略 + 产品化

写入策略回答：什么时候存？存什么？怎么存？
  → 触发条件、提取粒度、存储格式、置信度

召回策略回答：什么时候取？怎么取？取多少？
  → 触发时机、召回路径、排序规则、数量上限

失效策略回答：什么时候忘？冲突怎么办？
  → 衰减规则、冲突消解、用户否决、project 隔离

产品化回答：用户如何感知和控制记忆？
  → 记忆面板、/memory 命令、透明度、可控感
```
