# 策略产品案例：长任务中"约束遗忘"问题的策略设计与迭代

## 案例背景

**场景**：用户给 Agent 一段长指令：

> "帮我分析这份财报 PDF，提取营收、利润、现金流三个指标，做成表格，然后用中文写一段 200 字以内的摘要，最后把表格和摘要都保存为 `report.md`。"

**Badcase**：Agent 在前 5 轮成功提取了数据、做了表格，但在第 6 轮写摘要时，**忘记了"200 字以内"的约束**，写了 500 字。用户不满意。

---

## 第一步：从 Badcase 归因

策略产品经理打开 Langfuse 追踪链路，看到事件流：

```
Turn 1: TOOL_CALL(file_read, "财报.pdf") → TOOL_OUTPUT(3000 tokens)
Turn 2: TOOL_CALL(data_extract, "营收/利润/现金流") → TOOL_OUTPUT(800 tokens)
Turn 3: TEXT("表格已生成...") → 用户确认
Turn 4: TOOL_CALL(table_format, markdown) → TOOL_OUTPUT(400 tokens)
Turn 5: TEXT("表格完成，开始写摘要...")
Turn 6: LLM 推理 → TEXT(500字摘要)  ← ❌ 违反"200字以内"约束
```

**归因分析**：

| 可能原因 | 验证方式 | 结论 |
|---------|---------|------|
| 模型能力不足 | 用同样 prompt 在 fresh context 中测试 | 模型能遵守 200 字约束 → **不是模型问题** |
| 上下文窗口被挤占 | 检查 Turn 6 时 context 中各层 token 分布 | 工具输出占 4200/8000 tokens，用户原始指令被 scroll 系统压缩到只剩 50 tokens → **根因** |
| 记忆未召回 | 检查 memory 中是否存储了"200 字"约束 | 没有 → **次因** |

**根因定位**：上下文分层策略中，用户原始指令（含约束条件）在 scroll 压缩时被过度裁剪，而工具输出（大段数据）占据了大部分窗口。

---

## 第二步：提出假设

> **假设**：如果在上下文压缩时，对用户指令中的"约束条件"（数字、时间、格式要求）做**分层保护**——即约束条件永不压缩、工具输出可摘要压缩——则长任务中的约束遵守率会显著提升。

---

## 第三步：设计策略规则

设计的策略规则（对应 QwenPaw 的 `context/scroll` 层 + `builder.py` 中间件链）：

```
上下文分层策略 v1：

Layer 0（永不压缩）：
  - 系统提示词（system prompt）
  - 用户原始指令中的约束条件（通过 NER 提取：数字、时间、格式词）

Layer 1（轻度压缩）：
  - 用户后续对话（保留完整，但超过 3 轮时摘要早期轮次）

Layer 2（可压缩）：
  - 工具输出结果（超过 500 tokens 时自动摘要）
  - 推理过程（reasoning_delta 不进入下一轮 context）

Layer 3（可丢弃）：
  - 已完成的中间步骤的工具调用详情
  - 被用户否定的方案
```

**具体规则**：

```python
# 约束提取规则（伪代码）
def extract_constraints(user_message):
    """从用户消息中提取不可压缩的约束条件"""
    constraints = []
    # 数字约束："200字以内"、"3个指标"
    constraints += regex.findall(r"\d+\s*(字|个|行|页|秒|分钟)", user_message)
    # 格式约束："表格"、"markdown"、"中文"
    constraints += regex.findall(r"(表格|JSON|markdown|中文|英文|PDF)", user_message)
    # 时间约束："今天"、"2024年"
    constraints += regex.findall(r"\d{4}年|今天|本周|上月", user_message)
    return constraints

# 上下文预算分配规则
CONTEXT_BUDGET = {
    "layer_0_constraints": 500,    # 约束条件最多 500 tokens
    "layer_1_recent_chat": 2000,   # 近期对话最多 2000 tokens
    "layer_2_tool_output": 3000,   # 工具输出最多 3000 tokens（超出则摘要）
    "layer_3_discard": float("inf"), # 中间步骤详情可丢弃
}
```

---

## 第四步：设计实验验证

设计了 A/B 实验：

| 维度 | 对照组（当前策略） | 实验组（分层保护策略） |
|------|-----------------|---------------------|
| 上下文压缩 | 按时间顺序 FIFO 裁剪 | 按分层策略裁剪 |
| 约束保护 | 无 | Layer 0 永不压缩 |
| 工具输出 | 保留原始 | 超 500 tokens 自动摘要 |

**评测指标**（基于 HarnessEvent 标准化事件流计算）：

```python
metrics = {
    # 核心指标
    "constraint_compliance_rate": 约束遵守率（摘要是否≤200字）,
    "task_completion_rate": 任务完成率（表格+摘要+保存是否都完成）,

    # 过程指标
    "avg_context_utilization": 上下文窗口利用率,
    "tool_output_compression_ratio": 工具输出压缩比,
    "constraint_recall_rate": 约束召回率（约束条件是否在 context 中）,

    # 用户体验指标
    "avg_turns_to_complete": 平均完成轮次,
    "user_satisfaction_score": 用户满意度（thumbs up/down）,
}
```

---

## 第五步：实验结果与迭代

**v1 实验结果**（100 个长任务 badcase 回测）：

| 指标 | 对照组 | 实验组 v1 | 变化 |
|------|-------|----------|------|
| 约束遵守率 | 34% | 71% | +37pp ✅ |
| 任务完成率 | 62% | 78% | +16pp ✅ |
| 平均完成轮次 | 8.2 | 6.5 | -1.7 ✅ |
| 工具输出压缩比 | 1.0x | 3.2x | 显著压缩 ✅ |
| **新问题：数字提取准确率** | 95% | 82% | **-13pp ❌** |

**归因 v1 的新问题**：工具输出被过度摘要，导致财报中的具体数字（营收 12.3 亿）在摘要中丢失精度。

---

## 第六步：策略迭代 v2

调整规则：

```
v2 改进：
- Layer 2 工具输出压缩时，数字类信息（金额、百分比、日期）永不压缩
- 新增规则：表格/结构化数据保留原始，仅压缩叙述性文本
- 约束提取增加"比较类"约束（"比去年增长"、"高于行业平均"）
```

**v2 实验结果**：

| 指标 | 对照组 | v1 | v2 |
|------|-------|-----|-----|
| 约束遵守率 | 34% | 71% | **89%** |
| 任务完成率 | 62% | 78% | **91%** |
| 数字提取准确率 | 95% | 82% | **94%** |
| 平均完成轮次 | 8.2 | 6.5 | **5.8** |

---

## 第七步：策略产品化

验证有效后，将策略规则产品化：

1. **写入 Loop Engineering 层**：新增 `ConstraintGate`（StopGate 的一种），在每次循环迭代后检查"约束条件是否仍被遵守"，如果不遵守 → `INTERRUPT_AND_CONTINUE`，注入提醒消息
2. **写入上下文层**：将分层压缩策略固化为 `ScrollPolicy` 的默认配置
3. **写入评测体系**：将"约束遵守率"纳入常规回归评测集，每次模型/策略迭代都自动跑

---

## 案例总结：策略产品经理的核心能力

| 能力维度 | 本案例体现 |
|---------|----------|
| **技术理解** | 知道上下文窗口是有限资源，理解 scroll 压缩机制、token 分布 |
| **策略抽象** | 从"忘了 200 字约束"这个具体 badcase 中抽象出"约束条件分层保护"的通用策略 |
| **数据驱动** | 用标准化事件流计算指标，用 A/B 实验验证，而不是拍脑袋 |
| **迭代思维** | v1 解决了一个问题但引入了新问题，通过归因快速定位并迭代 v2 |
| **产品化能力** | 验证有效的策略固化为 Gate / Policy / 评测基准，形成可复用资产 |
